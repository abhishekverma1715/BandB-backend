## 2026-09-07 - `$regex` vs `$text` Semantics & N+1 Queries
**Learning:** While upgrading from `$regex` to `$text` indices provides massive performance gains (O(N) to O(log N)), `$text` relies on word-stemming and language-aware parsing, which fundamentally alters search semantics compared to substring-matching `$regex`. We cannot blindly substitute `$text` for `$regex` if exact partial matches (e.g. searching "pla" for "plastic") are required by the client. Additionally, found a classic N+1 query pattern in `routes/categories.ts` where a `.map()` iterates over categories and queries `Product.countDocuments()` individually.
**Action:** Always verify client expectations before migrating to `$text`. For N+1 query patterns, refactor using MongoDB's `$group` inside `aggregate()` to fetch all counts in a single O(N) database round-trip.
